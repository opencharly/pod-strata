# 2026.323.1821 — feat(strata)!: extract the strata POD into pod-strata (base: pod-cdi)

## Summary

The Strata **POD** moves out of `opencharly/layer-strata` into this repo, and lands on the POD
substrate instead of the VM one.

- **`box/strata` moves here**, and its `base:` becomes **`pod-cdi.pod-cdi`**. It was
  `cachyos.cachyos` — a VM-contract GPU base whose driver user-space is baked into the image — on an
  image deployed **as a pod**. A pod does not own its driver: the kernel module is host-global, so
  the driver user-space arrives per container from the NVIDIA container toolkit's CDI spec.
  `layer-cdi` owns that rule, and its own plan steps FAIL the build when a host-coupled driver
  library or an `nvidia*` binary is baked (`cdi-no-baked-driver-libs`,
  `cdi-no-baked-driver-binaries`) — the boundary is a property of the artifact, not of a reviewer's
  attention.
- **`check-strata-gpu-pod` moves here**, ported 1:1 from `opencharly/layer-strata#24`'s head: that
  PR's assertions, `timeout:`s, `eventually:` windows and comments, with the single difference this
  repo makes — `image: strata` resolves here. It stays out of the umbrella's default roster and is
  run on demand.
- **The box skill moves here** (`.agents/skills/strata/`), rewritten for the runtime contract this
  family adopts, while `/charly-strata:strata-layer` stays with the candy that owns the bake.

The box inherits the layer's hardening posture **verbatim** — `security: security_opt:
[no-new-privileges]`, the deploy-side expression of the zero-escalation measurement (the real stack
runs `--cap-drop ALL --security-opt no-new-privileges` under `userns=host`, workload as the mapped
host user). `cap_drop` is not expressible in `#Security`; that gap is filed, not worked around
(`## Filed issues`).

## Change classification

A NEW repository, so **nothing that consumed it breaks at this merge** — there was no consumer.
The subject still carries the cutover marker, because what this PR *publishes* is a changed contract
for everyone who deploys the `strata` image, and naming that is the honest half of the marker:

**Breaking change + rollback:** for a consumer of the `strata` image, three things change and none
of them is a rename-with-an-alias: (1) the **env surface** is upstream v0.2.16's — `STRATA_RUN_ARGS`
and `STRATA_OVERLAY_JSON` are gone (they were charly's own runtime, deleted with the entrypoint that
implemented them), `GGUF_DIR` becomes `MODEL_PATH`, `LOW_RAM`/`LAYER_SPLIT`/`REINSTALL`/
`KV_STREAMING`/`RESIDENT_BUDGET_GIB`/`HOST`/`CONFIG` are ignored with a warning, and the tuning a
deployment used to pass as argv is now a setup choice (`CONTEXT`, `STRATA_SET`, `TUNE`); (2)
**`API_KEY` is `secret_require`**, so `charly config` mints it and the unit carries
`Secret=…,type=env,target=API_KEY` — a deployment that relied on the old `STRATA_API_KEY` projection
must move its key to `charly/secret/API_KEY`; (3) the **store layout** moves to `/data/Strata-data`
by upstream's own one-way migration, which a v0.1.x image cannot read back. **Rollback:** revert
this PR — the content still exists in `opencharly/layer-strata` at `v2026.323.1751` until its PR-2 lands, so
the revert restores the pre-cutover state exactly; after PR-2 has merged, a revert here is only
complete together with a revert there.

## Filed issues

Every issue this cutover filed for a finding on this leg, each non-blocking and separable from the
change:

- opencharly/pod-cdi#7 — the base's `layer-cdi` pin and a consumer's can disagree (here
  `v2026.323.0302` from `pod-cdi`'s chain and `v2026.323.1259` from the candy), and the resolver
  settles it silently: newest wins, no diagnostic. Measured harmless on this closure — the bed
  passed at `2026.323.1728` and at `2026.323.1759` — so the fix is `pod-cdi`'s own pin advance, and
  a hand-pin anywhere else would be the same rule in a second place (`PIN-CHAIN.md` §5d).
- opencharly/charly#1217 — an `import:` inside a discovered box document passes `charly box
  validate` but never joins the composition, and `charly box generate` then blames a candy for the
  missing distro chain. Found by this leg; this repo uses the project-root placement and documents
  the measurement in the import's own comment.
- opencharly/spec#398 — `#Security` cannot express `cap_drop`, so a pod cannot declare the
  least-privilege posture the CDI+bind class actually runs at. Inherited with the `security:` block,
  which declares the one option a pod CAN declare.
