# 2026.325.1855 — fix(pins): advance the pod-cdi import so the namespace loads and the base carries the carrier fix

## Summary

Advances the `pod-cdi` import pin to its merged release, and configures the family's runtime bed
for the two venue conditions that running it exposed (opencharly/pod-strata#2).

```diff
-    - pod-cdi: '@github.com/opencharly/pod-cdi:v2026.323.1302'
+    - pod-cdi: '@github.com/opencharly/pod-cdi:v2026.325.1329'
```

1. **The imported namespace loads again.** At `v2026.323.1302` it resolves a distro-arch generation
   whose imported beds predate distro-arch#74, and the loader refuses the deploy-level bed member
   that carries no `host:`. Because the umbrella imports this repo by local path, that took down
   every umbrella verb that loads the project — `task verify`, `task init`, `task sync`,
   `task worktree`, and the pre-push pin gate with them.
2. **The base carries today's carrier fix.** `v2026.325.1329` composes the distro-arch release that
   stops emitting the retired `COPY --from=<carrier> .agents/skills` step
   (opencharly/pod-cdi#10). This pod's box is `base: pod-cdi.pod-cdi`, so a consumer-side `arch`
   import could not have delivered it.

**And the bed's own venue settings, both measured.** `check-strata-gpu-pod` binds the operator's
model store, so it inherits the *deployment's* run settings. Running it twice exposed two
interactions that made it fail for reasons unrelated to the pin:

```diff
         CONTEXT: "65536"
+        # both measured; see How tested
+        STRATA_SET: "idle-unload=0 vram-reserve-mib=512"
```

- `idle-unload=0` — the store carries `idle_unload_s: 300` (the five-minute release,
  opencharly/layer-strata#26). Between the vision probe's 30 s retries the model unloaded, so most
  attempts paid a cold load.
- `vram-reserve-mib=512` — with the operator's reserve of 0 the model takes the whole card, the first
  prefill of the picture round-trip had nothing to allocate, and the engine died:

  ```
  strata serve: WARNING: only 13 MiB of VRAM free at the start of this request (below 512 MiB) …
  prefill gemm: cublasGemmEx f16: cuBLAS status 14
  ```

  supervisord then restarted the engine on a ~60 s cycle (35 failed probe attempts over 30 minutes).
  512 MiB is the figure the engine's own warning asks for on this card.

A bed asserts behaviour, so it configures the venue that behaviour needs; **the deployment keeps its
operator-chosen reserve of 0**.
