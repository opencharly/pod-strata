# 2026.326.0203 — feat(pin): layer-strata v2026.326.0119 — keyless bed, and a same-repo owner for the box skill

## Summary

Follows the producer (opencharly/layer-strata#29, ledger `P10`) and fixes a defect the pin bump
surfaced.

- **The pin advances** from `v2026.323.1751` to `v2026.326.0119`: the tag whose candy declares
  `API_KEY` as `secret_accept` and maps `STRATA_ACCESS` / `STRATA_NO_API_KEY` onto upstream's two
  hardcoded entrypoint lines.
- **`check-strata-keyless-pod`** — the same image, store and GPU venue, with
  `STRATA_NO_API_KEY: "1"`, and ONE step of its own: `strata-keyless-gate` asserts `/health`
  publishes `api_key: false`. That step FAILS on a keyed deployment (and on any build that lost the
  producer's launcher patch), which the inherited posture-branched `strata-api-gate` cannot witness.
- **The box skill gets a same-repo owner.** The pin bump made the loader refuse this repo:
  `skill "strata": no body — no .agents/skills/strata/SKILL.md exists at the repo root of the
  owning candy "strata"`. The node named a FOREIGN candy and had only ever resolved against a
  duplicate body in layer-strata's tree that the v0.2.16 cutover deleted. Per opencharly/sdk#611 a
  node's `owner:` must name a candy defined in the same repo as its body, so a new `strata-skills`
  carrier candy owns the node, carries the body, installs it at the uid-1000 account's
  `~/.agents/skills`, and proves the install with an ADE check; the box composes it.
  **It is declared INLINE in the root `charly.yml`, not under `candy/`:** the collector reads the
  body at the OWNING REPO's root, while a candy under `candy/` gets its build stage context FROM
  ITS OWN DIRECTORY (`COPY candy/<name>/ /`) — the first bed run failed there with
  `"/.agents/skills": not found`. An inline candy takes its declaring `charly.yml`'s directory as
  its source dir (sdk `deploykit.CandyCopySource`), which is exactly the repo root, so the
  collector and the build stage read the same tree.
- The two comments that said "the candy REQUIRES the key" now state the real contract, and
  `AGENTS.md` records the owner rule on this repo's own skill surface.
